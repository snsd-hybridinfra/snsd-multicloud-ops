# 뉴스·실습·개인 프로젝트를 연결한 인프라 포트폴리오 정리

> 기준일: 2026-09-22  
> 대표 프로젝트: [SNSD Financial Hybrid-Ready Internal Developer Platform](../README.md)

## 포트폴리오 방향

뉴스를 모아 놓는 대신, 산업 동향에서 기술적 문제를 뽑고 직접 구성·장애·보안 테스트로 확인한 결과를 남긴다.

```text
산업 동향 → 해결할 문제 → 실습 설계 → 정상·장애·보안 검증 → 결과와 한계 → 대표 프로젝트에 적용
```

대표 프로젝트는 **가상 증권사를 위한 비운영 Private Cloud IDP**다. 사용자 경험 → 승인된 조합형 서비스 → 정책·승인 → 불변 매니페스트 → 자동화 → OpenStack/k3s → 금융 네트워크 언더레이 순서로 설명한다. Zero Trust는 플랫폼 전체에 걸친 보안·검증 영역으로 별도 상태를 유지한다.

현재 퍼블릭 클라우드 연결이 구현·검증되지 않았으므로 **Hybrid-Ready**라고 쓴다. 실제 증권 거래나 고객 데이터를 처리하는 시스템으로 소개하지 않는다.

## 대표 프로젝트에서 이미 정리한 내용

| 영역 | 현재 상태 | 포트폴리오에서 제시할 근거 |
|---|---|---|
| 플랫폼 목표·경계 | 로컬 거버넌스 검증 | [플랫폼 개요](platform/README.md), [목표 아키텍처](platform/target-architecture.md), [기준선](platform/architecture-baseline.yaml) |
| 승인형 서비스 카탈로그 | 8개 조합형 상품의 로컬 설계·검증 | [카탈로그](platform/composite-service-catalog.yaml), [구현 로드맵](platform/implementation-roadmap.md) |
| Private IaaS 경로 | `VM_APPLICATION_STACK`의 요청·승인·모의 실행 매니페스트 경로를 로컬 검증 | [구현 로드맵](platform/implementation-roadmap.md), [Private IaaS 계약](platform/private-iaas-golden-path.yaml) |
| AI Agent Sandbox | 상태 머신·격리·자격증명·예산·추적 계약과 일부 로컬 구현 | [샌드박스 계약](platform/ai-agent-sandbox.yaml) |
| 금융 네트워크 | 목표 설계 단계 | [목표 아키텍처](platform/target-architecture.md) |
| 퍼블릭 클라우드 어댑터 | 보류 | [기준선](platform/architecture-baseline.yaml) |

**로컬 검증은 실제 OpenStack 배포나 k3s 종단 간 운영을 뜻하지 않는다.** 파일 존재만으로 통합 완료를 주장하지 않고, 각 영역의 설계·로컬 테스트·실제 런타임 증적을 구분한다.

## 기술 학습 흐름

```text
Routing & Switching
    ↓
BGP / ECMP
    ↓
Spine-Leaf와 EVPN / VXLAN
    ↓
Network Automation
    ↓
Private Cloud와 Kubernetes Networking
    ↓
Zero Trust와 AI Agent Security
    ↓
AI Data Center Infrastructure
```

아래 실습은 **포트폴리오 계획**이다. 실제 수행·검증하지 않은 항목을 완료 성과로 표시하지 않는다. 각 실습을 수행하면 설정 파일, 토폴로지, 명령 출력, 정상·장애 비교 결과와 해석을 추가한다.

## 우선순위별 실습

### 1. BGP / ECMP Spine-Leaf

- **프로젝트 연결:** 금융 네트워크 언더레이의 경로 다중화와 장애 수렴.
- **구성:** 2 Spine / 2 Leaf, Leaf–Spine eBGP, 동일 목적지에 대한 복수 경로.
- **검증:** BGP 이웃과 라우팅 테이블의 ECMP 경로 확인 → Spine 또는 링크 장애 → 통신·경로 수렴 확인 → 복구 후 경로 재형성.
- **증적:** 토폴로지, 장비 설정, `show ip bgp summary`, `show ip route`, 장애 전후 `traceroute`. 사용 이미지와 명령은 실제 실습 환경에 맞춘다.
- **현재 표시:** 계획. 금융 네트워크 자체는 설계 단계다.

### 2. EVPN / VXLAN

- **프로젝트 연결:** 테넌트와 워크로드의 네트워크 분리.
- **먼저 정리할 개념:** IP Underlay, VTEP, VNI, BGP EVPN Control Plane, L2VNI와 L3VNI.
- **다음 실습:** Underlay 연결 확인 → VTEP와 EVPN 경로 확인 → 동일·서로 다른 세그먼트의 통신과 격리 확인.
- **증적:** 토폴로지, VTEP·EVPN 출력, 허용·거부 통신 결과.
- **현재 표시:** 개념 정리 및 실습 계획을 구분.

### 3. RESTCONF / Python 네트워크 자동화

- **프로젝트 연결:** 장비 상태 조회와 운영 검증의 자동화.
- **구성:** RESTCONF/YANG API로 인터페이스 또는 BGP 이웃 상태를 읽고 JSON을 정제한다.
- **검증:** 동일 상태를 CLI와 API에서 조회해 값과 오류 처리를 비교한다.
- **증적:** 비밀정보를 제거한 코드·샘플 응답·CLI 대조 결과.
- **확장:** BGP Neighbor 자동 점검과 상태 변화 감지.

### 4. IAM / STS

- **프로젝트 연결:** 향후 퍼블릭 클라우드 어댑터의 최소 권한과 단기 자격증명 설계.
- **핵심 질문:** 장기 Access Key를 애플리케이션에 넣지 않고 역할 위임과 만료되는 자격증명으로 작업을 수행할 수 있는가?
- **검증:** 별도 AWS 학습 환경에서 허용·거부 권한과 자격증명 만료 동작을 확인한다.
- **경계:** 이 학습은 현재 IDP에 AWS가 연결됐다는 증거가 아니다.

### 5. HA / 복구

- **프로젝트 연결:** 현재 범위에서는 합성 서비스의 백업, 복원, 선언적 재구축.
- **검증:** 장애 전 상태 기록 → 백업·복원 또는 재구축 → 데이터·서비스 복구 확인 → 실제 소요 시간 측정.
- **경계:** Multi-AZ, Multi-Region DR, Active-Active는 별도 학습 주제로만 정리한다. 이 저장소의 현재 플랫폼에 다중 사이트 DR이 구현된 것처럼 쓰지 않는다.

### 6. AAA / RADIUS

- **프로젝트 연결:** 관리망 접근 제어와 운영자 인증.
- **구성:** 별도 랩에서 802.1X/RADIUS 인증·인가 정책을 구성한다.
- **검증:** 승인된 사용자 접근과 미승인 사용자 거부, 정책 변경 및 로그를 확인한다.
- **증적:** 비밀정보와 개인 식별자를 제거한 정책·인증 결과.

### 7. AI Agent Security

- **프로젝트 연결:** 현재 `AI_AGENT_SANDBOX`의 격리, 승인, 단기 자격증명, 제한된 외부 통신, 예산, 감사·추적.
- **검증:** 정책 문서와 로컬 테스트를 먼저 연결하고, 실제 런타임 검증은 승인된 범위의 증적만 별도로 표기한다.
- **핵심 질문:** Agent가 Git, 모델 API, 셸 및 네트워크를 사용할 때 권한·비용·데이터 유출 범위를 어떻게 제한하는가?
- **경계:** 로컬 계약이나 모의 테스트를 전체 외부 서비스 통합 완료로 승격하지 않는다.

### 8. AI Data Center Network

- **프로젝트 연결:** 네트워크 엔지니어링의 장기 확장 방향.
- **학습 주제:** GPU 클러스터의 East-West 트래픽, Spine-Leaf, BGP/ECMP, RoCEv2, 혼잡 제어, 광 연결.
- **문서 방식:** 산업 동향·개념·직접 검증 가능한 실습을 분리한다. 특정 속도나 장비 도입을 현재 프로젝트의 성과로 적지 않는다.

## 문서별 공통 양식

각 실습 README에는 다음을 넣는다.

1. **문제와 선택 이유:** 뉴스 또는 대표 프로젝트에서 발견한 필요.
2. **범위와 상태:** 계획 / 설계 / 로컬 검증 / 런타임 검증.
3. **토폴로지·구성:** 재현에 필요한 버전, 설정과 입력.
4. **정상 검증:** 기대 결과와 실제 출력.
5. **장애·보안 검증:** 실패 주입, 거부 경로, 복구 절차.
6. **결과와 한계:** 관측한 것과 아직 검증하지 못한 것.
7. **대표 프로젝트 연결:** 해당 결과가 IDP의 어떤 설계·운영 문제에 도움이 되는지.

## GitHub 첫 화면 소개 문안

> 네트워크를 기반으로 Private Cloud, Security, AI Infrastructure까지 확장하는 인프라 포트폴리오입니다. 대표 프로젝트는 가상 증권사 환경을 위한 Hybrid-Ready Private Cloud IDP이며, 승인된 서비스 요청부터 정책 검증, 자동화, 관측과 회수까지 단계적으로 구현하고 있습니다. BGP/ECMP, EVPN/VXLAN, 네트워크 자동화 및 보안 실습은 이 플랫폼의 문제를 독립적으로 검증하는 랩으로 연결합니다. 각 항목은 설계, 로컬 테스트, 실제 런타임 검증 상태를 구분해 공개합니다.

## 게시 순서

1. 대표 프로젝트의 목표·아키텍처·현재 검증 상태를 먼저 소개한다.
2. 이미 재현 가능한 로컬 검증 결과를 근거 문서와 연결한다.
3. BGP/ECMP → EVPN/VXLAN → RESTCONF/Python 순으로 네트워크 랩을 쌓는다.
4. IAM/STS, 복구, AAA/RADIUS, AI Agent Security를 프로젝트 경계와 연결한다.
5. 뉴스는 별도 산업 동향 문서에서 **동향 → 기술적 문제 → 해당 실습** 링크로 압축한다.

이 순서로 정리하면 뉴스에서 얻은 관심사와 실제 개인 프로젝트의 구현·검증 범위가 하나의 이야기로 이어진다.
