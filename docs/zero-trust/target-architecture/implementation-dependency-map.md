
# Implementation Dependency Map

The dependency model is phase-gated, profile-driven, and package-specific. Phase exit criteria are prerequisites for the next phase; architecture documentation never satisfies a runtime gate.

`ZT-ID-001` is an implemented and runtime-validated Phase 1 identity package for one bounded non-production validator endpoint. Its synthetic policy suite remains locally validated, while the accepted runtime scope covers a dedicated validator account/group, forced command, SSH restrictions, exact sudo allowlist, recovery, and deterministic allow/deny evidence. It does not establish centralized identity, MFA, OIDC, application RBAC, production validation, or maturity. `ZT-DEV-001` is implemented and partially runtime validated for six classified aliases and one mandatory live VM; broad endpoint management, EDR/XDR, patch automation, and device authorization remain absent. `ZT-APP-001` is implemented and partially runtime validated for two applications, four workloads, a partial direct-image SBOM, and one unchanged non-critical Alloy pilot; immutable provenance, signing, transitive vulnerability coverage, and broad deployment enforcement remain absent. `ZT-DATA-001` is implemented and partially runtime validated for seven metadata-only assets, manual labels, detection-only DLP, and one isolated synthetic restore; enterprise governance, dynamic access, platform encryption, live backup/restore, blocking DLP, and continuous analysis remain absent. `ZT-SYS-001` is implemented and partially runtime validated for seven bounded systems, five safe matched configuration authorities, and existing fixed read-only runtime validators; OpenStack remains `CURRENT_DEGRADED` at 46/0/4, and complete PAM, credential lifecycle, continuous FIM, broad hardening, automatic recovery, and full system restore remain absent. `ZT-AUTO-001` is implemented and partially runtime validated for fixed R0-R3 handlers, default-deny policy, deterministic plans, proposal-only governance, and one partial cross-domain read-only execution; arbitrary execution, R4-R8 mutation, external notification, autonomous response, repeatability, scheduling, SOAR, and maturity remain absent. `ZT-ID-002` remains a separate later Phase 2 candidate. `ZT-VIS-001` now has accepted single-node persistent storage for approved sanitized JSONL. `ZT-VIS-002` remains protected Phase 2 preparation and does not inherit that authority. Identity-based Grafana access remains a Phase 2 design use case. IaC, Configuration as Code, and Policy as Code convergence waits for cross-domain signal and enforcement validation.

`implementation-dependency-map.yaml` is the machine-readable authority. It records Phase 1 as `PARTIAL` / `PARTIALLY_VALIDATED` / `NOT_COMPLETE`, preserves `ZT-SCH-001` as a design-only boundary, and records future packages only as design, not-started, unassessed, or roadmap-only work.
